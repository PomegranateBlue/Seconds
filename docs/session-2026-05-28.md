# seconds — 세션 브리핑 (2026-05-28)

> 이 문서는 별도 대화(데스크탑 Claude 등)에 컨텍스트 없이 붙여넣어 기획을 이어가기 위한 스냅샷이다.

---

## 1. 프로젝트 한 줄 요약

브라우저에서 **최대 30명**이 모이는 **3D 공간**. 텍스트 채팅 + 근접 음성 채팅(WebRTC P2P) + Three.js 구체 캐릭터 이동. **비용 최소화가 최우선이다(Vercel Hobby + Supabase 무료 티어).**

## 2. 핵심 기술 결정 (이유 포함)

| 영역 | 선택 | 이유 |
|---|---|---|
| 호스팅 | Vercel Hobby (무료) | 비용 0. 단 서버리스라 상시 WebSocket 서버는 못 둠 |
| 실시간 채팅 / 위치 동기화 | **Supabase Realtime — Broadcast 채널** | 별도 백엔드 서버 안 만들기 위함. 클라이언트가 anon key로 직접 연결 |
| 접속 인원 (최대 30) | **Supabase Realtime — Presence** | 동일 |
| 음성 | **WebRTC P2P** | 서버 미디어 비용 0. 시그널링은 Supabase 채널 재사용 |
| 음성 메시 과부하 방지 | **근접 4~6명만 P2P 연결** | 30명 전원 메시는 P2P로 못 버팀 |
| 3D 렌더링 | **React Three Fiber (R3F) + drei** | 사용자 선호: 개발 시간/수고 절약, 고수준 추상화. 단순 게이미피케이션용이라 본격 3D는 아님 |
| 스타일 | Next.js 16 App Router + Tailwind 4 + TypeScript | `create-next-app` 기본 |

## 3. 비용 가드레일 (절대 금지)

- 유료 SFU / 미디어 서버 (LiveKit Cloud, Agora 등) 도입 금지
- 30명 음성 전원 메시 연결 금지
- 새 유료 서비스/유료 티어 필요 시 코드 쓰기 전에 먼저 확인

## 4. 오늘 완료한 것 — Milestone 1: 빈 3D 공간

- `app/components/Scene.tsx` — R3F `<Canvas>`에 조명·구체·카메라 셋업
- `app/components/BackgroundMesh.tsx` — 정육면체 방 (한 변 50)
  - 바닥 1장 (planeGeometry)
  - 벽 4장 (boxGeometry, 두께 0.2)
  - 천장 없음 (의도)
- 카메라: `position: [0, 2, 4], fov: 60`
- `OrbitControls`로 마우스 회전/줌
- 조명: `ambientLight(0.4)` + `directionalLight`
- `app/page.tsx`는 `<main className="w-screen h-screen">`로 Scene 감쌈

## 5. 오늘 결정한 새 방향 ⭐

> **UI → 기능** 순서로 개발한다 (기능 → UI 가 아님).

즉 다음 단계는 곧장 Supabase 채팅 기능을 붙이는 게 아니라, **앱 전체의 UI 뼈대**부터 그린다. 이 결정에 따라 다음 대화의 첫 작업이 결정됨.

## 6. 다음에 결정해야 할 것 (= 데스크탑 Claude와 같이 기획할 거리)

UI 우선 방향으로 갔을 때 떠오르는 결정 거리들:

1. **화면 구성 / 레이아웃**
   - 3D 공간이 차지하는 영역 vs 채팅 UI 위치는?
   - 채팅창: 오른쪽 사이드바 / 하단 오버레이 / 토글식?
   - 접속자 목록은 어디에? (Presence 결과 표시)
   - 닉네임 입력 / 입장 화면이 따로 있나, 익명 즉시 입장인가?
2. **시점**
   - 1인칭 (구체 안에서 보기) vs 3인칭 (구체 위 카메라) vs 자유 시점?
   - 캐릭터 이동 입력은 WASD / 클릭 이동 / 둘 다?
3. **분위기 / 그래픽 톤**
   - 현실적 / 카툰 / 미니멀? (방 색감, 조명, 폰트, 색 팔레트)
   - 음악 / 효과음 들어가나?
4. **온보딩**
   - 처음 들어왔을 때 안내가 필요한가? (조작법 등)
5. **모바일 대응**
   - 모바일 지원 범위는? (3D는 모바일에서 발열 이슈 가능)
6. **기능 범위 확정**
   - 텍스트 채팅 = DM 있음/없음, 채널 분리 있음/없음
   - 음성 = 항상 켜짐 / 푸시투토크 / 토글
   - 구체 외형 커스터마이징은 v1에 포함? (색만? 이름표?)

## 7. 사용자 협업 스타일 (다음 대화에서도 동일하게 적용해야)

- 한국어로 답한다.
- 개발 초보 (전공자지만 완성 프로젝트 경험 없음, 학습이 목표).
- 큰 변경을 한 번에 쏟지 말고 작은 단계로 쪼개고 중간에 확인받기.
- 코드 쓰기 전에 "무엇을, 왜 이렇게" 1~3문장 설명.
- 가능하면 사용자가 직접 코드 치게 시키고 리뷰해주는 방식 선호.
- 라이브러리 선택: **고수준 추상화 우선** (개발 시간/수고 절약).
- 과한 칭찬·위로 금지. 정확한 피드백 선호.
- 모르면 모른다고 말할 것. 추측 금지.

## 8. 코드 현황 (간략)

```
app/
├── page.tsx                       # <Scene /> 한 줄 렌더
├── layout.tsx                     # (create-next-app 기본)
└── components/
    ├── Scene.tsx                  # 'use client' + R3F Canvas
    └── BackgroundMesh.tsx         # 방 (바닥 + 벽 4)
```

- `next` 16.2.6, `react` 19.2.4
- `three`, `@react-three/fiber`, `@react-three/drei`
- `@types/three` (devDependency)
